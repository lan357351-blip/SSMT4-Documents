# 导出处理链

导出处理链是 TheHerta4 蓝图版的核心机制，负责从蓝图节点图中收集物体信息、解析处理路径、执行节点操作，最终生成导出数据。

## 蓝图的收集与解析

### 蓝图树的定位

导出流程首先需要定位当前正在编辑的蓝图树（Blueprint Tree）。蓝图树是一种特殊的 Blender 节点树，类型标识为 `SSMTBlueprintTreeType`。定位蓝图树的优先级为：

1. **当前编辑的节点树**：如果用户正在节点编辑器中编辑蓝图，直接使用该蓝图
2. **运行时记录的蓝图**：使用最近一次操作过的蓝图
3. **工作空间名称匹配**：根据全局配置的工作空间名称查找蓝图

### 输出节点检测

蓝图必须包含一个 **Generate Mod**（Result Output）节点作为导出入口。如果缺少该节点，解析将直接报错终止。

### 正向解析模式

TheHerta4 使用**正向解析模式**（Forward Parse Mode），从 Object Info 节点出发，沿着连接关系向 Generate Mod 节点方向遍历。这比旧版的反向解析模式更精确，能够正确处理链路分叉和物体切换等复杂场景。

## 链路遍历与分裂

### 处理链的概念

**处理链（Processing Chain）** 表示一个物体从 Object Info 节点到 Generate Mod 输出节点的完整路径。每条处理链包含：

- **object_name**：当前物体名称（可能经过重命名）
- **original_object_name**：原始物体名称
- **node_path**：经过的节点路径
- **shapekey_params**：形态键参数列表
- **rename_history**：重命名历史记录
- **swap_node_option_values**：物体切换节点的选项值
- **vertex_group_process_nodes**：顶点组处理节点列表
- **vertex_group_mapping_nodes**：顶点组映射节点列表

### 链路遍历过程

1. **收集起始节点**：找到蓝图中所有 Object Info 节点和 MultiFile Export 节点
2. **嵌套蓝图收集**：递归收集 Blueprint Nest 节点引用的嵌套蓝图中的 Object Info 节点
3. **逐节点正向遍历**：从每个起始节点出发，沿输出连接向 Generate Mod 方向遍历
4. **记录节点参数**：每经过一个节点，提取其参数签名并记录到处理链中

### 链路分叉（Fork）

当一个节点的输出连接到多个下游节点时，链路会发生**分叉**。分叉的处理方式：

- **单连接**：直接继续遍历
- **多连接**：深拷贝当前处理链，为每个分支创建独立的处理链

分叉时物体会被复制，复制后的命名规则：
- 普通副本：`{名称}_chain{序号}`
- 如果原始名称以 `_copy` 结尾：`{名称}_chain{序号}_copy`

### 物体切换节点的分叉

物体切换（Object Swap）节点有多个输入口（选项_0、选项_1、...），每个输入口对应一个切换选项。当链路经过物体切换节点时：
- 记录连接到哪个输入口（选项索引）
- 该索引值将作为 `$swapkey` 条件比较的依据

### 静音节点的跳过

被静音（Mute）的节点会被跳过，但其输出连接会继续传递到下游节点。

### 嵌套蓝图的处理

当遍历到 Blueprint Nest 节点时：
1. 进入嵌套蓝图树
2. 在嵌套蓝图中继续遍历
3. 到达嵌套蓝图的 Result Output 节点后，返回父蓝图
4. 继续从 Blueprint Nest 节点的输出连接遍历

## 链路去重与合并

### 去重机制

遍历完成后，会根据处理链的哈希值进行去重。哈希值由以下因素决定：
- 经过的节点类型和参数签名
- 物体名称

如果两条链路的哈希值完全相同，则只保留一条。

### 同名物体处理

当同一个物体被多条处理链引用时（例如一个 Object Info 节点连接到多个分支），系统会：
1. 检测同名物体的链路数量
2. 如果超过 1 条，复制物体创建独立副本
3. 副本命名规则：`{名称}_dup{序号}` 或 `{名称}_dup{序号}_copy`

### 处理链组合并

参数签名完全相同的处理链会被合并为一个**处理链组（Chain Group）**，共享相同的导出配置。

## 物体名称的变化

在整个导出流程中，物体名称会经历以下变化：

| 阶段 | 名称变化 | 示例 |
|------|---------|------|
| 前处理创建副本 | 添加 `_copy` 后缀 | `Body` → `Body_copy` |
| 链路分叉 | 添加 `_chain{N}` 后缀 | `Body_copy` → `Body_chain1_copy` |
| 同名去重 | 添加 `_dup{N}` 后缀 | `Body_copy` → `Body_dup1_copy` |
| Rename 节点 | 按规则替换字符串 | `4c11c155-288-7068.名称` → `4c11c155-288-7068.新名称` |
| Bone Palette 节点 | 添加 `_BPE` 后缀 | `Body_copy` → `Body_BPE_copy` |

## 节点的顺序执行

处理链解析完成后，系统会按链路顺序依次执行以下操作：

1. **物体切换节点集成**：收集所有 Object Swap 节点，分配 swapkey 索引，生成条件参数
2. **重命名节点执行**：按链路顺序对物体执行重命名操作
3. **顶点组处理节点执行**：对物体执行顶点组的重命名、合并、清理等操作
4. **Bone Palette 导出节点执行**：对物体执行骨骼调色板本地化处理
5. **跨 IB 节点处理**：收集跨 IB 映射信息，生成条件配置
6. **DrawCall 模型构建**：将处理链转换为最终的导出数据模型

## 后处理链

在导出处理链之外，Generate Mod 节点还有一个专用的后处理输出端口，连接到后处理节点链。后处理节点在导出完成后执行，对生成的文件和配置表进行修改。

后处理节点的详细说明请参考 [后处理](/theherta4/后处理/后处理介绍) 章节。
