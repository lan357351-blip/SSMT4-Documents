# 前处理

前处理是导出流程的第一阶段，在蓝图解析和导出之前执行。前处理的目的是将 Blender 场景中的原始物体准备为可供导出处理链使用的标准化数据。

前处理目前没有对应的蓝图节点，它是在点击 **Generate Mod** 时自动执行的固定流程。

## 前处理流程

前处理按以下步骤依次执行，每个步骤都会对所有目标物体进行操作：

### 1. 收集目标物体

前处理首先收集需要处理的所有物体名称，包括：

- 蓝图中 Object Info 节点引用的物体
- 多文件导出节点（MultiFile Export）中列出的物体

收集完成后会进行去重，确保每个物体只被处理一次。

### 2. 创建物体副本

对每个目标物体创建一个独立副本，副本的命名规则为 `{原始名称}_copy`。

创建副本的具体操作：
- 复制物体对象及其数据（网格、形态键等）
- 将副本链接到当前场景的集合中
- 如果副本已存在，则直接复用

::: tip 为什么要创建副本？
前处理的所有操作都作用于副本而非原始物体，这样可以保护原始模型数据不被修改。导出完成后，副本会被自动清理删除。
:::

### 3. 应用约束

对副本物体应用所有 Blender 约束（Constraints），例如：
- 骨骼约束（Copy Transforms、Track To 等）
- 对象约束（Child Of、Floor 等）

应用约束后，约束的效果会被"烘焙"到物体上，约束本身被移除。

### 4. 应用修改器

对副本物体应用所有可见的修改器（Modifiers）：

- **有形态键的物体**：使用专用的优化方法应用修改器，确保形态键数据不丢失
- **无形态键的物体**：直接应用修改器

应用修改器后，修改器的效果被"烘焙"到网格数据中，修改器本身被移除。

### 5. 三角化

对所有网格物体执行三角化操作：
- 将所有四边形（Quad）和多边形（N-gon）面转换为三角形
- 使用 `BEAUTY` 方法进行三角化，以获得更好的三角面分布

::: warning 三角化的必要性
游戏引擎要求所有网格面都是三角形，因此三角化是导出前的必要步骤。
:::

### 6. 应用变换

对所有副本物体应用变换：
- 应用位置（Location）
- 应用旋转（Rotation）
- 应用缩放（Scale）

应用变换后，物体的世界矩阵变为单位矩阵，所有变换信息被"烘焙"到顶点数据中。

### 7. 应用形态键

对所有有形态键的物体应用形态键：
- 将当前形态键的混合结果应用到基础网格上
- 移除所有形态键

::: info 形态键在导出链中的角色
虽然前处理会应用形态键，但如果蓝图中存在形态键节点（ShapeKey），导出流程会在前处理之前单独处理形态键的导出配置。前处理中的应用形态键操作主要针对不需要保留形态键信息的物体。
:::

### 8. 非镜像工作流恢复（可选）

如果启用了非镜像工作流（Non-Mirror Workflow），前处理会执行非镜像物体的恢复操作：
- 将镜像修改器生成的半边数据恢复为完整的对称数据
- 确保导出的模型包含完整的几何信息

### 9. 更新蓝图节点引用

前处理完成后，蓝图中的 Object Info 节点和 MultiFile Export 节点会被更新：
- 将节点中引用的物体名称从原始名称改为副本名称（`{名称}_copy`）
- 确保后续的导出处理链操作的是副本物体

### 10. 缓存机制（可选）

如果启用了前处理缓存，前处理会：
- 计算每个物体的哈希值（基于物体数据）
- 如果缓存命中，直接从缓存加载已处理的副本
- 如果缓存未命中，执行正常的前处理流程并保存到缓存

缓存可以显著减少重复导出时的前处理时间。

## 前处理后的清理

导出完成后，前处理会自动执行清理操作：
- 删除所有 `_copy` 后缀的副本物体
- 恢复蓝图节点中的物体引用（从副本名称改回原始名称）
- 清理孤立数据（无引用的网格、材质、纹理、图像）
